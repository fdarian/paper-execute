Purpose: `designer` CLI — every backend is a subcommand group with `mcp`, `cc` and `acp`. `designer paper mcp` serves one `execute` codemode tool for Paper via executor QuickJS; `designer paper cc [...args]` launches Claude Code as the Opus `director` agent with a Haiku `designer` subagent as its hands (prompts: shared `assets/designer/agent.md` plus `director.md` / `designer.md`), this MCP server, `paper-refs` plugin, user-level settings and global CLAUDE.md skipped) with args after `--` passed through to `claude`. `designer brilliant mcp|cc|acp` does the same against Brilliant (default `http://127.0.0.1:3333/mcp`, env `BRILLIANT_MCP_URL`, config `brilliantMcpUrl`); the sandbox global is `brilliant`, and `cc` skips `paper-refs`.
Stack: Bun, TypeScript, Effect v4 RC, executor core APIs, MCP SDK, Biome.
Commands: `pnpm install` (pnpm workspace: `packages/*`, shared versions in the `catalog:`; patches stay registered in the root `pnpm-workspace.yaml`), `bun run check:type`, `bun run check:lint`, `bun test`, `bun run build` (→ `dist/cli/designer`), `bun run src/cli.ts paper mcp` / `paper cc -- <claude args>` / `paper acp`.
Architecture: `src/backend/*` defines `DesignBackend` (name, slug, MCP URL resolution, `cliPath` to its command group, instructions) with `paper.ts` / `brilliant.ts`; engine, preamble, and server instructions take one. `src/cli.ts` declares the Effect CLI commands (`mcpCommand(backend)` / `ccCommand(backend)` / `acpCommand(backend)` factories, one subcommand group each for `paper` and `brilliant`; `cc` has boolean `-c`/`-r` flags (Effect CLI has no optional-value flags, so `designer paper cc -r <id>` puts `--resume` right before the passthrough and the id is the leading positional) plus a variadic arg; `cc` and `acp` (all backends) share an optional `--cache-ttl <5m|1h>` that sets `promptCacheTtl` and `subagentPromptCacheTtl` in the `--settings` JSON after `cc.settings` (absent = Claude Code's automatic default); Effect CLI rejects other unknown flags, so those need `--`: `designer paper cc -- --verbose`), `src/mcp/stdio.ts` boots stdio MCP, `src/mcp/instructions.ts` holds the server instructions (shared with `cc`, which appends them plus the loaded plugins' instructions — via `src/plugin/boot.ts`, no executor/Paper needed — to both agent prompts because agent prompts replace the system prompt and subagents don't get MCP instructions), `packages/agent-team` (`@paper-execute/agent-team`, exports `src/index.ts`, no build step) is the generic Claude Code launcher: an `AgentTeam` (`agents` with already-filled prompts, `main`, `mcpServers`, `pluginDirs`, `addDirs`, `enabledPlugins`, `env`) plus `TeamSettings` (`cc.inheritSettings`, `cc.settings`, cache TTL) go into `buildClaudeArgs(team, settings, { continue, resume, passthrough })` (pure argv builder) / `runClaude` (spawn) / `runAcp` (claude-agent-acp in-process; no `--strict-mcp-config` equivalent, so it merges `team.mcpServers` into the adapter's `mcpServers` and `team.addDirs` into its `additionalDirectories`, and takes `ANTHROPIC_MODEL` and the settings `model` from the main agent; call `redirectConsoleToStderr()` first because stdout carries JSON-RPC). `--dangerously-skip-permissions`, `--strict-mcp-config` (keeps user-scope MCP servers like a native `brilliant` entry from loading beside ours) and `--setting-sources project,local` are unconditional. `statusLine`/`theme`/`editorMode`/`outputStyle` are carried from the user's `$CLAUDE_CONFIG_DIR/settings.json` via `--settings` because `--setting-sources` drops user settings; the config's optional `cc.inheritSettings` (`{ <settings key>: true | [sub-keys] }`) inherits more, literal `cc.settings` merges over it, and the team's `enabledPlugins` win; `--setting-sources` doesn't stop ancestor-directory CLAUDE.md/rules like `~/.claude/CLAUDE.md` from loading, so use `cc.settings.claudeMdExcludes`, including real paths behind symlinks. The package reads only the `cc` key of the same config file as the root plugin config (same discovery order; the root schema ignores `cc`). It also has `selfCommand(args)` / `selfMcpServer(args)` (this same program as a command: `[execPath, ...args]` when compiled, `[execPath, Bun.main, ...args]` from a checkout), `materializePlugin(name, files)` (→ `$TMPDIR/<name>-<hash>`) and the shared Effect CLI flags `ccFlags` / `cacheTtlFlag`. `src/designer/*` is what stays designer-specific: `designerTeam(launch)` (`team.ts`: Opus `director` + Haiku `designer` agents, whose prompts use `{{name}}` / `{{slug}}` / `{{tools}}` placeholders filled from the `DesignerLaunch`, our MCP server keyed by `launch.slug`, `frontend-design@claude-plugins-official` enabled), `run.ts` (`runDesignerClaude` / `runDesignerAcp`: boot plugins, build the launch, hand the team to the package), `launch.ts` (`DesignerLaunch`: name, slug, `tools`, `mcpArgs`, instructions, `pluginDirs`, `addDirs`, `agents` (extra agents the director can delegate to; keys can't be `director`/`designer`), `env`, optional `designerTools` that restricts only the designer subagent), built by `executorLaunch(backend, booted)` in `src/backend/launch.ts`; `assets.ts` is a Bun macro embedding `assets/designer/*` — agent prompts and the `paper-refs` plugin — as strings, `paper-refs.ts` materializes the plugin. `launches.test.ts` pins the full argv and ACP session options of `paper`/`brilliant` launches (prompts as hashes, in `__snapshots__`); update the snapshot only when a launch is meant to change. `src/mcp/server.ts` wraps the single tool, `src/executor/engine.ts` wires executor + Paper MCP + loaded plugins, `src/plugin/*` defines plugin/config/loader/registry flow, `src/icons/*` handles the built-in Phosphor icon plugin (`svg-assets.ts` is a Bun macro embedding the SVGs, so the compiled binary needs no `node_modules`); `src/image/*` the built-in local-image plugin (`plugins.image.get(path)` → `{ src (data: URI), width, height, mimeType }`; dimensions via `image-size`).
Notes: `assets/designer/` sits outside `src/` on purpose: `paper-refs/hooks/register.ts` imports types from `claude-code`, which this repo can't resolve, so it must stay out of the TS program (and Biome). Packages import each other by name and use relative imports inside (`#/*` is root-only). Use `@executor-js/*/core` imports (the bare `.` export is the promise façade), keep Effect at `4.0.0-rc.115`, and treat all sandbox tool calls as async.
Gotchas (non-obvious):
- `packages/agent-team/package.json` uses concrete dependency versions, not `catalog:` or `workspace:*`: pnpm can't resolve those when another repo consumes the package over `github:...#path:`.
- `patches/@executor-js%2Fplugin-mcp@1.5.28.patch` fixes an upstream bug: plugin-mcp's `/core` build imports `tool`/elicitation types from the SDK root (promise façade, which lacks them) instead of `@executor-js/sdk/core`. Without the patch, importing `@executor-js/plugin-mcp/core` throws at load. Present in 1.5.28 and 2.0.0.
- `pnpm-workspace.yaml` registers 1.6.8 executor patches that replace beta-only schema constructors with their RC equivalents; refresh them when updating executor packages.
- `patches/@executor-js__codemode-core@1.6.8.patch` anchors `FENCED_CODE_BLOCK` with `^`: upstream's fence stripping matches anywhere in the source, so 3+ literal ``` runs in user code (e.g. Brilliant edit fences) would truncate it to the text between two of them. Covered by `src/mcp/server.test.ts`.
- `createExecutor` needs a writable credential provider (`providers: [...]`) — even the no-auth (`template: "none"`) Paper connection fails `connections.create` with `CredentialProviderNotRegisteredError` otherwise. `engine.ts` registers an in-memory one.
- Published `/core` types expose plugin extensions loosely (`executor.mcp` is `any`); `engine.ts` pins it to `McpPluginExtension` so the Effect error/requirement channels stay typed.
- The sandbox wraps every tool call in `{ ok, data }`; `src/executor/preamble.ts` unwraps it and Paper's CallToolResult (`plugins.icon.get("acorn")` → SVG string; `paper.*` → structuredContent, then shallow merge of nonempty all-text JSON objects with disjoint keys, including a single object; throws on failure). Invalid JSON, non-object JSON, key collisions, or non-text blocks fall back to a string for one text block or the unchanged content array. Use `t.summary` / `f.nodes` for tree/search results and `emit(block)` for native MCP content; returned arrays are JSON text.
- Plugin config discovery order is `./paper-execute.config.json` then `~/.config/paper-execute/config.json` then built-in default `{ "plugins": ["icon", "image"] }`; the same config carries `cc.inheritSettings` for the launcher.
- External plugin files can import `definePaperPlugin` from `paper-execute/plugin`. To prove local resolution from `~/.config/paper-execute/plugins/*.ts`, run `bun link` in this repo, then `bun link paper-execute` plus `bun add zod` or `bun add effect` in that plugin directory.
- Compiled binary (`bun build --compile`): `--bytecode` forces CommonJS, so no top-level `await` in `src/cli.ts` (it uses `BunRuntime.runMain`). `--compile-autoload-package-json` and `--compile-autoload-tsconfig` are required for external plugin files — without them the binary ignores `main`/`exports` of their dependencies and the `#/*` alias of the linked `paper-execute/plugin`, so plugins fail with "Cannot find module".
