Purpose: `designer` CLI — every backend is a subcommand group with `mcp`, `cc` and `acp`. `designer paper mcp` serves one `execute` codemode tool for Paper via executor QuickJS; `designer paper cc [...args]` launches Claude Code as the Opus `director` agent with a Haiku `designer` subagent as its hands (prompts: shared `assets/designer/agent.md` plus `director.md` / `designer.md`), this MCP server, `paper-refs` plugin, user-level settings and global CLAUDE.md skipped) with args after `--` passed through to `claude`. `designer brilliant mcp|cc|acp` does the same against Brilliant (default `http://127.0.0.1:3333/mcp`, env `BRILLIANT_MCP_URL`, config `brilliantMcpUrl`); the sandbox global is `brilliant`, and `cc` skips `paper-refs`. `designer draft mcp --dir <abs>|cc [--project <name>]|acp [--project <name>]|view [--project] [--port]` is a third, desktop-free surface: designs are plain HTML files in `~/.config/draft/projects/<project>` (env `DRAFT_PROJECTS_DIR` overrides the root; default project = git repo or cwd basename), the agents edit them with native Read/Write/Edit, and one MCP tool `render` returns a PNG; `view` serves a live gallery.
Stack: Bun, TypeScript, Effect v4 RC, executor core APIs, MCP SDK, Biome.
Commands: `pnpm install`, `bun run check:type`, `bun run check:lint`, `bun test`, `bun run build` (→ `dist/cli/designer`), `bun run src/cli.ts paper mcp` / `paper cc -- <claude args>` / `paper acp` / `draft cc`.
Architecture: `src/backend/*` defines `DesignBackend` (name, slug, MCP URL resolution, `cliPath` to its command group, instructions) with `paper.ts` / `brilliant.ts`; engine, preamble, and server instructions take one. `src/cli.ts` declares the Effect CLI commands (`mcpCommand(backend)` / `ccCommand(backend)` / `acpCommand(backend)` factories, one subcommand group each for `paper` and `brilliant`, plus `draft`; `cc` has boolean `-c`/`-r` flags (Effect CLI has no optional-value flags, so `designer paper cc -r <id>` puts `--resume` right before the passthrough and the id is the leading positional) plus a variadic arg; `cc` and `acp` (all backends) share an optional `--cache-ttl <5m|1h>` that sets `promptCacheTtl` and `subagentPromptCacheTtl` in the `--settings` JSON after `cc.settings` (absent = Claude Code's automatic default); Effect CLI rejects other unknown flags, so those need `--`: `designer paper cc -- --verbose`), `src/mcp/stdio.ts` boots stdio MCP, `src/mcp/instructions.ts` holds the server instructions (shared with `cc`, which appends them plus the loaded plugins' instructions — via `src/plugin/boot.ts`, no executor/Paper needed — to both agent prompts because agent prompts replace the system prompt and subagents don't get MCP instructions), `src/designer/*` is the surface-agnostic `cc` launcher (plus `acp.ts`: `runDesignerAcp(buildLaunch)` runs claude-agent-acp in-process for any backend, taking the same `buildLaunch` as `runDesignerClaude` and building from it through the same `designerAgents(launch)` / `designerMcpServer(launch)` / `designerSettings` builders as `buildClaudeArgs`; it has no `--strict-mcp-config` equivalent and merges our server into the adapter's `mcpServers` and `launch.addDirs` into its `additionalDirectories`): it takes a `DesignerLaunch` (`launch.ts`: name, slug, `tools`, `mcpArgs`, instructions, `pluginDirs`, `addDirs`, optional `designerTools` that restricts only the designer subagent) built by `executorLaunch(backend, booted)` in `src/backend/launch.ts` or `draftLaunch(project)` in `src/draft/launch.ts`; `buildClaudeArgs` is the pure argv builder (agent prompts use `{{name}}` / `{{slug}}` / `{{tools}}` placeholders the launcher fills; the MCP config key is `launch.slug` and `--strict-mcp-config` keeps user-scope MCP servers like a native `brilliant` entry from loading beside ours; `assets.ts` is a Bun macro embedding `assets/designer/*` — agent prompts and the `paper-refs` plugin — as strings; the plugin is materialized to `$TMPDIR/designer/paper-refs-<hash>`; the MCP config points back at this same program; `statusLine`/`theme`/`editorMode`/`outputStyle` are carried from the user's `$CLAUDE_CONFIG_DIR/settings.json` via `--settings` because `--setting-sources project,local` drops user settings; `--settings` also always enables `frontend-design@claude-plugins-official`; the config's optional `cc.inheritSettings` (`{ <settings key>: true | [sub-keys] }`) inherits more and literal `cc.settings` merges over it, designer entries win; `--setting-sources` doesn't stop ancestor-directory CLAUDE.md/rules like `~/.claude/CLAUDE.md` from loading, so use `cc.settings.claudeMdExcludes`, including real paths behind symlinks), `src/mcp/server.ts` wraps the single tool, `src/executor/engine.ts` wires executor + Paper MCP + loaded plugins, `src/plugin/*` defines plugin/config/loader/registry flow, `src/icons/*` handles the built-in Phosphor icon plugin (`svg-assets.ts` is a Bun macro embedding the SVGs, so the compiled binary needs no `node_modules`), `src/draft/*` is the draft surface (`project.ts` paths, `server.ts` static server that expands `<i data-icon="<phosphor name>" data-weight>` into inline SVG via `HTMLRewriter`, `renderer.ts` + `cdp.ts` headless Chrome over raw CDP with no dependency (executable: env `DRAFT_CHROME_PATH`, else macOS Google Chrome), `mcp.ts` the `render` tool, `gallery.ts`/`view.ts`, `instructions.ts` agent-facing rules); `src/image/*` the built-in local-image plugin (`plugins.image.get(path)` → `{ src (data: URI), width, height, mimeType }`; dimensions via `image-size`).
Notes: `assets/designer/` sits outside `src/` on purpose: `paper-refs/hooks/register.ts` imports types from `claude-code`, which this repo can't resolve, so it must stay out of the TS program (and Biome). Use `@executor-js/*/core` imports (the bare `.` export is the promise façade), keep Effect at `4.0.0-rc.115`, and treat all sandbox tool calls as async.
Gotchas (non-obvious):
- Draft frame height is the content height measured against a 900px initial viewport, so `100vh` / `height:100%` on html/body collapse or inflate it; frames needing a fixed height use a px `min-height` (also stated in `src/draft/instructions.ts`). Draft `cc` limits the designer subagent to Read/Write/Edit/Glob/Grep/`mcp__draft__render` (no Bash) and grants the project folder with `--add-dir`.
- `patches/@executor-js%2Fplugin-mcp@1.5.28.patch` fixes an upstream bug: plugin-mcp's `/core` build imports `tool`/elicitation types from the SDK root (promise façade, which lacks them) instead of `@executor-js/sdk/core`. Without the patch, importing `@executor-js/plugin-mcp/core` throws at load. Present in 1.5.28 and 2.0.0.
- `pnpm-workspace.yaml` registers 1.6.8 executor patches that replace beta-only schema constructors with their RC equivalents; refresh them when updating executor packages.
- `patches/@executor-js__codemode-core@1.6.8.patch` anchors `FENCED_CODE_BLOCK` with `^`: upstream's fence stripping matches anywhere in the source, so 3+ literal ``` runs in user code (e.g. Brilliant edit fences) would truncate it to the text between two of them. Covered by `src/mcp/server.test.ts`.
- `createExecutor` needs a writable credential provider (`providers: [...]`) — even the no-auth (`template: "none"`) Paper connection fails `connections.create` with `CredentialProviderNotRegisteredError` otherwise. `engine.ts` registers an in-memory one.
- Published `/core` types expose plugin extensions loosely (`executor.mcp` is `any`); `engine.ts` pins it to `McpPluginExtension` so the Effect error/requirement channels stay typed.
- The sandbox wraps every tool call in `{ ok, data }`; `src/executor/preamble.ts` unwraps it and Paper's CallToolResult (`plugins.icon.get("acorn")` → SVG string; `paper.*` → structuredContent, then shallow merge of nonempty all-text JSON objects with disjoint keys, including a single object; throws on failure). Invalid JSON, non-object JSON, key collisions, or non-text blocks fall back to a string for one text block or the unchanged content array. Use `t.summary` / `f.nodes` for tree/search results and `emit(block)` for native MCP content; returned arrays are JSON text.
- Plugin config discovery order is `./paper-execute.config.json` then `~/.config/paper-execute/config.json` then built-in default `{ "plugins": ["icon", "image"] }`; the same config carries `cc.inheritSettings` for the launcher.
- External plugin files can import `definePaperPlugin` from `paper-execute/plugin`. To prove local resolution from `~/.config/paper-execute/plugins/*.ts`, run `bun link` in this repo, then `bun link paper-execute` plus `bun add zod` or `bun add effect` in that plugin directory.
- Compiled binary (`bun build --compile`): `--bytecode` forces CommonJS, so no top-level `await` in `src/cli.ts` (it uses `BunRuntime.runMain`). `--compile-autoload-package-json` and `--compile-autoload-tsconfig` are required for external plugin files — without them the binary ignores `main`/`exports` of their dependencies and the `#/*` alias of the linked `paper-execute/plugin`, so plugins fail with "Cannot find module".
